Règles pour tenir le planning

  • 100 % gratuit : aucune carte bancaire, aucun abonnement. Quota atteint : étaler le travail ou utiliser un modèle local.
  • Termine la conception (phase 0) avant de reprendre le code : chaque fonctionnalité doit avoir une métrique et un test prévus.
  • Ne rien perfectionner avant la fin de la phase 3 : un projet moyen mais fini vaut mieux qu’un projet parfait inachevé.
  • En retard ? Supprimer d’abord le cache sémantique (jour 11), jamais le benchmark : les chiffres comptent le plus.
  • Une ligne de journal par jour dans le README (fait, bloqué). Un commit par jour.
  • Bloqué plus de 45 minutes : copier le message d’erreur exact et demander de l’aide.
  • Énergie, CO₂e et eau côté API sont des estimations, pas des mesures : l’écrire dans le README et à l’oral. Vérifier les noms exacts des modèles Gemini avant de commencer.
  • Le projet est présentable dès la fin du jour 10 : ajouter le lien GitHub aux candidatures.
